02 / FOUR CATEGORIES

Different jobs. Different evidence.

Everyday work

Text-answer preference, with style controlled. A signal for general assistant tasks.

Coding

Preference on web development tasks. This does not cover every programming language or workflow.

Images

Text-to-image and image-editing results, weighted equally. Models need both tests to qualify.

Research

Search-answer preference, with style controlled. It does not independently establish factual accuracy.

03 / THE METRICS

Make the comparison fair before averaging.

RELATIVE RANK / 0–100

Position within a test.

Each Arena rating becomes a percentile within the collected four-provider cohort. Equal ratings share a midrank. A score of 100 means the highest relative position in that test; it is not 100% accuracy.

SHARED TESTS ONLY

Same evidence. Same weights.

Comparisons use tests available for every selected model. Missing results are not treated as zero. A broader average requires at least two shared tests; a single test stays a category score.

Votes, published uncertainty bounds and test dates provide context in the comparison. Small ranking differences should not be read as proven superiority.

04 / DATA WORKFLOW

From changing sources to one usable dataset.

  1. 01

    Collect

    Python reads Arena results and the public OpenRouter model catalog. Plan details are reviewed against provider documentation.

  2. 02

    Validate

    Check structure, exact model identities and source records before computing relative scores.

  3. 03

    Build

    Generate one complete data.js file. If validation fails, the previous release stays in place.

  4. 04

    Publish

    Run the updater manually, review the output and replace the published file through GitHub.

OpenRouter supplies model specifications, separately from benchmark scores. The refresh needs no API key. It does not automatically verify subscription access or changing usage caps.
